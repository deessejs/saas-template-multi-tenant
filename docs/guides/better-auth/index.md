## Code Structure

```
packages/auth/src/auth.ts             — better-auth config (SINGLE SOURCE OF TRUTH)
packages/database/src/schema/auth.ts   — drizzle tables + relations (CLI-generated)
packages/email/                       — email transport + transactional templates
```

**Rule:** all better-auth configuration lives in `packages/auth/src/auth.ts`. Never inline auth config in routes or components.

## Code State (2026-07-28)

- `packages/auth/src/auth.ts`: ~80 lines, monolithic config. Organization plugin wired with `requireEmailVerificationOnInvitation: true`. **No auto-create on signup** (dropped in commit `73830a1` per `NO_ORG_RECOVERY.md`).
- `packages/database/src/schema/auth.ts`: generated by `pnpm auth:generate`. Currently holds the 4 base tables (`user`, `session`, `account`, `verification`). **Organization tables (`organization`, `member`, `invitation`, `team`) are NOT yet generated** — schema regeneration is part of issue #12 (`impl/12-feat-auth-wire-organization-plugin-with-auto-creat`) and is required before any `auth.api.*` calls touching org state will work.
- Email verification: active. `sendOnSignUp: true` and `sendOnSignIn: true`, fire-and-forget pattern via `void sendAuthEmail(...)`. See `email.md`.
- Open bugs: [#9070](https://github.com/better-auth/better-auth/issues/9070) (`session.create.before` ordering) — moot while we do not auto-create on signup, but relevant if a future change reintroduces signup-time org creation. [#9710](https://github.com/better-auth/better-auth/issues/9710) (`useActiveOrganization` stale after sign-in) — workaround documented in `pitfalls.md` §3 and applied in `apps/app/lib/auth-client.ts`.
- Resolved risks (see `pitfalls.md` for the fix history): §4 useSecureCookies, §5 trustedOrigins localhost gate, §6 sendOnSignUp temp bypass, §7 ORPCError in auth middleware.
